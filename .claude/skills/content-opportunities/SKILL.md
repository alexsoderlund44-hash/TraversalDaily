# Content opportunities

Maintains `MKT/seo-pages.csv` and the narrative `MKT/04-seo-opportunity-map.md`. Rules and paths: `MKT/00-system.md`.

## Inputs

`MKT/keywords.csv`, `MKT/03-competitors.md`, GSC queries if connected, and the game's own data: `data/schedule.js` (730 dated puzzles with start, destination, twist and, on hand-made days, title and blurb), `data/cities.js`, the weekday `RHYTHM` in `js/traverse.js`.

## Quality gate (apply before scoring)

A page idea passes only if all are true:
- It answers something a searcher wants that the game itself does not already answer on the play page.
- It has unique content we own (a puzzle's real constraints, the planner's route, player stats, our own write-up), not text rewritten from Wikipedia or Rome2Rio.
- At scale (templated pages) each instance has enough distinct data to stand alone. Google's scaled-content-abuse policy (`https://developers.google.com/search/docs/essentials/spam-policies#scaled-content`) is the test: would we build it if search engines did not exist?
- It does not undercut Traversle + (the archive is the paid product); if it reveals solutions, note the trade-off in `notes`.

## Score each idea

Columns: `id, page, url, type (landing|recap|series|guide|comparison|tool|faq), intent, audience, primary_kw, secondary, difficulty (1-5), value (1-5), effort (1-5), evidence, priority, status`.
`priority = round(value * (6 - difficulty) / effort, 1)`; ≥4 build now, 2–4 next, <2 park. Explain the top 5 in the map file with the SERP evidence.

## Building pages

When a page is approved, implement it as a static page in this repo (pages are generated by `tools/build-designs.py`; per-puzzle pages should be generated by a tool script the same way `tools/build-schedule.js` writes data), add it to `sitemap.xml`, link it from at least two existing pages, and give it a unique title, description and canonical. Then add a backlog row to measure it (GSC impressions after 28 days).
